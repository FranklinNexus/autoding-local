# 独立运行研究构建

将 `research/android/src`、`res` 和 Manifest 编译成 `org.autoding.research` 更新包，接入随 APK 安装的中文 OCR 模型。Gradle 仅在构建目录生成适配 AGP 8 的 Manifest 副本；源 Manifest 保留，合并后移除网络权限。

```powershell
./research/tools/Build-Standalone.ps1
# 已缓存依赖后可追加 -Offline；可用 -GradleUserHome 指定研究缓存。
```

需要 JDK 17、Gradle 8.14.3、Android SDK 35 和 Build Tools 35.0.0。Gradle 命令及缓存均未找到时，复用 `research/ocr` 的 wrapper。首次构建电脑需要访问依赖仓库；手机端 OCR 无需网络权限。

输出 `build/AutoDing-standalone-research.apk` 及对应 SHA-256 文件，包名与原研究包相同，版本号 2。首次克隆构建时，如本地尚无 `build/research-test.jks`，脚本生成一把本机研究测试密钥；后续构建始终复用已有密钥并核对 APK 证书，已有文件不会被覆盖。密钥已被 Git 忽略，应保留备份。同包名更新要求与手机上已装版本的签名一致：新电脑自行生成的另一把密钥只适合自己的首次安装，更新原安装需复用原构建机的密钥。测试密钥和测试签名不作为正式发行凭据。

兼容入口 `research/tools/Build-Research.ps1` 委托同一 Gradle 构建，并把相同的已签名 APK 复制到旧路径 `build/AutoDing-research.apk`，不再运行旧的裸 Java 编译流程。两种入口均检查中文模型、ARM 识别库与无网络权限。

## 一次手机独立试用

`OneShotRunner` 接通了 `setAlarmClock` 60 秒单次触发、手机原生 PIN 解锁、导航到考勤页、新截图与本机 OCR。界面有“60 秒后独立读取考勤（不点击）”和一次下班实测入口；后者会实际操作下班卡，需按当次试用目的安排。仅明确识别下班操作且窗口仍为同一新画面时，流程最多提交一次点击，之后重新截图核对新的实际签退时间。点击请求完成与回执核验成功分别记录。

PIN 在手机“设置本机加密 PIN”窗口填写，使用 AndroidKeyStore AES-GCM 加密，密文保存在应用私有的 credential-encrypted 存储。失败的输入尝试被本地阻断，排查后通过本机 PIN 设置处理；PIN 和原始图片不进入日志。重启后首次凭据解锁仍需人工完成，日常锁屏解锁单独验收。

这是一项执行完即停止的试用，未接入生产日常排程，也未自动套用“实际签到时间 + 工作时长”的签退规则。已接通功能和已通过实机验收分开记录，实时状态与证据见 `research/RESULTS.md`。USB 拔出接墙充、隔夜及重启等条件分别验收；PC 任务暂停后的单次运行也须记录当时 USB 状态。

## 严格拔线墙充入口

先暂停既有 PC 配套任务并记录原状态，再实际拔掉电脑 USB、接充电头，在手机界面选择“已接充电头：3 分钟后测试下班”，确认“开始 3 分钟倒计时”。界面先核对 USB 状态已知且断开、充电电源为 `1` / `2` / `4`；未满足时显示“尚未安排”，通过后直接安排 180 秒后的系统闹钟。确认“已安排 3 分钟后测试”后按电源键锁屏息屏，从安排时刻起至少等待 6 分钟再接回电脑，结束后按原状态恢复 PC 任务。

`TrialStartGuard` 在实际闹钟触发、取得唤醒锁和 PIN 输入之前，核对 `requiresDetachedCharger=true` 的试次：USB 状态已知且 `false`、电源类型为 `1` / `2` / `4`、锁屏且息屏，才继续。界面安排阶段用户仍在操作手机，实际锁屏息屏以闹钟触发时核对为准。未知 USB、连接电脑、未充电或未锁屏息屏返回固定错误码并停止考勤输入；电源 `2` 也可由 USB 充电头产生，需与数据连接为断开合并判断。普通单次试用保留原入口，不据其通过宣称拔线验收。DUMP 保护的 `trial-checkout-wall` 默认直接安排严格 180 秒试次，`trial-cancel` 取消本次研究闹钟。

v24 观察到电脑实际断开约 6 分 50 秒，但 App 到重连附近才记录处理断开并建立闹钟，具体内部原因未确定。当前源码已移除 USB 事件等待和自动安排入口，使用上述拔线后手机手动安排流程；文档不将旧等待入口当作已通过能力。新入口的安装、当前页只读识别及完整墙充实测分别记证据。

启动检查 11 项纯 Java 夹具通过，与 v27 的一次实际墙充完整闭环分开记载。相关原生变更累计 161 项纯 Java 检查通过，最终构建及验签、模型、网络权限检查通过，lint 为 0 错误、17 警告；并非每项都在最后一轮重复运行。研究流程仍未接入本机每日排程和动态工作时长规则。

## 截图接入

```java
FrameOcr.recognize(bitmap, capturedAtEpochMs, result -> {
    // result: accepted, reason, date, checkIn, checkOut, freshTimeMs,
    //         actionLabel, actionBounds, diagnostics
});
```

传入后 Bitmap 所有权归 `FrameOcr`；异步读取全部结束后回收 Bitmap 和裁剪、关闭识别器，主线程恰好回调一次。不持久化图片或原始 OCR 文字。`freshTimeMs` 是截图时的 epoch 毫秒，允许最近 60 秒的画面，使用手机当前时区解释当天日期。

仅处理华为 1080×2400 竖屏参考布局及同宽高比缩放：上午 `[44,590,518,730]`，下午 `[506,590,840,730]`，操作和日期 `[310,1320,780,1605]`。下午裁剪避开右侧“早退/更新”标签。这些区域不扩展到个人信息区。日期、星期、状态、时间和实际记录有歧义时返回稳定错误码。

两张卡片在 OCR 前复制为可写的软件 Bitmap，只用浅灰覆盖参考图中蓝圈勾图标的矩形：上午 `[44,675,166,730]`、下午 `[506,675,612,730]`，坐标均为参考整屏坐标，按相同比例缩放。图标右侧的实际时间和上方计划标签保留，原截图其他区域不修改。这项预处理只适用于已验华为参考布局；字体或布局变化仍需重新验收，未知文字前缀继续拒绝。

`diagnostics` 仅输出各裁剪的行数、标题/实际状态/时间标记数量和固定行类别，省略原始文字与时间值；用于区分裁剪、OCR 格式和解析问题。

## 已观察早退确认页

`FrameOcr.recognizeEarlyCheckout(bitmap, capturedAtEpochMs, callback)` 使用独立入口，只验证已观察到的确认页和实际 OCR 按钮坐标。参考裁剪为拍照选填 `[40,1790,400,1980]`、备注选填 `[40,1985,400,2100]`、原因提示诊断 `[40,2090,420,2160]`；按钮 OCR 输入使用已观察完整底部 `[0,1750,1080,2400]` 保留模型上下文，但只将实际 OCR 框完整落在按钮区域 `[40,2220,1040,2360]` 的行送入按钮解析，其他行不参与匹配。提示裁剪避开已观察到的覆盖层起点 `y=2163`；其软件副本做固定灰度对比度拉伸，浅灰约 `206` 映射到 `27`，白色保持 `255`，不生成或补全文字。

“拍照(选填)”“备注(选填)”和“早退打卡”三项必须精确匹配，仅规范空白、中英文括号及不可见 Unicode 格式控制字符；两个选填标题可按原 OCR 行顺序连接后核对完整文字，按钮要求单行精确且唯一。原因提示是辅助诊断，低对比文字未精确识别或为空不阻断；若该区域明确出现“打卡”“必填”或“必选”等冲突词则停止。每项独立报告行数、精确匹配数量和固定类别，必需标签缺字返回具体区域错误码；包含标签或子序列的布尔值仅用于诊断，不参与接受判断。结果不含原始 OCR 文字，不填写原因，不保存原图，不扩展到其他弹窗。

入口沿用捕获时间不超过 60 秒的原生新帧检查，返回 `EarlyCheckoutResult.accepted/reason/label/bounds/freshTimeMs/diagnostics`。`bounds` 由按钮 OCR 的实际框平移至整屏坐标；上层仍需在动作前复核帧年龄、同一目标 App/窗口与布局版本，再读取新回执。代码集成、四区域实机识别和最终官方记录分别验收，本说明不声明本次实机已经通过。

## 已观察成功弹窗

`FrameOcr.recognizeCheckoutSuccess(bitmap, capturedAtEpochMs, callback)` 保留成功弹窗完整参考区域 `[115,1750,967,2140]` 作为 OCR 上下文，其软件副本仅将已观察绿色勾图标区域 `[350,1770,415,1840]` 填白；另独立识别避开图标的标题区域 `[420,1760,800,1860]`。独立标题必须只有一行，规范空白和格式字符后精确为“下班打卡成功”，真实文字框完整落在标题区域。完整上下文也必须恰好有一行位于已观察标题带；仅这一行使用独立识别的精确标题和真实框核对，其余上下文行全部保留。

随后严格解析唯一成功标题、唯一合法 `打卡时间:YYYY-MM-DD HH:mm` 和唯一“查看打卡结果”，核对顺序及三项真实 OCR 框在既定位置带。未知附加行、重复、其他动作及非法日期时间仍停止，没有用标题存在去忽略其他内容。诊断新增 `headingLineCount`、`independentHeadingExact`、`contextHeadingLineCount`；v24 的当前页只读实测分别为 `1`、`true`、`1`，三个位置带通过，识别官方 `14:41`，没有提交动作。日期与时间供上层继续核对当日、新旧及本次提交时刻；识别模块不宣告最终考勤页验收通过，也不点击按钮。

回调 `CheckoutSuccessResult` 包含 `accepted/reason/date/checkOut/actionBounds/freshTimeMs/diagnostics`，动作框来自实际“查看打卡结果”文字。未知附加文字、其他动作、重复记录或非法日期时间均停止；原始图片和 OCR 文字不保存，诊断只含固定类别与计数。

`OneShotRunner` 在成功弹窗精确识别后核对日期、原下班时间与本次提交分钟，持久化消费一次查看结果动作，再交由 `AttendanceNavigator` 等待精确原生“统计”标题并执行有界返回。返回后重新打开考勤页，只有新采集页面的当天日期、原实际上班时间及新的实际下班时间全部核对通过，才记录成功；查看结果点击或统计页导航均只是中间步骤。v27 在真实拔线墙充流程中通过本节路径，成功弹窗及新的考勤页均为同日 `15:37`，签到保持 `09:25`。各历史试次版本和开始条件见 `research/RESULTS.md`。

`actionBounds` 只取第三裁剪内 exact “下班打卡”或“更新打卡”的单个 OCR 行，并平移到整屏坐标；多个命中、未知标签或记录解析未通过均返回空。此模块只返回识别结果，点击和排程由上层研究流程负责。
